# 安卓目录检查与修复

日期：2026-10-05。

## 范围与步骤

检查 `android/` 中全部生产源码、构建配置、资源、测试及使用文档。构建产物不作为源码修改，根目录 Python、iOS 和参考机器人保持不变。

1. 分别审查认证与网络、接口与存储、页面与配置、全局会话与操作状态。
2. 对可确认的问题做最小修复，保留数字签到规则及雷达正常响应下的参考机器人算法。
3. 补充异常场景回归测试，运行单元测试、静态检查、设备测试及优化包构建。
4. 整理发现、验证结果和仍需真实设备验收的范围。

验证仅使用虚拟账号与离线响应，不执行真实登录或签到，不截图。

## 检查结果

| 问题 | 修复 |
| --- | --- |
| 取消请求后，阻塞连接可能仍等待网络超时 | 取消操作同时关闭连接，保留提交中断时的待确认语义 |
| 浏览器回调缺失时，循环内超时判断无法执行 | Cookie 清理和脚本回调各设 10 秒截止，完整认证另有 240 秒总上限 |
| 自动登录切换手动登录提示，可能复用旧的已销毁网页视图 | 按登录提示标识重建整个认证弹窗 |
| 重新认证后的第二次查询仍过期，界面却保留已登录状态 | 第二次过期也清除内存会话，保留原账号供重登 |
| 点击签到时登录刚好过期，准备阶段直接失败 | 只在提交前的只读检查中重新登录原账号；写入操作不自动重试 |
| 创建日志后读取本地数据失败，留下永久“处理中” | 将创建后的读取纳入统一失败处理，落盘为失败且不提交签到 |
| 核对结果返回未知签到形式，覆盖原日志的数字/雷达形式 | 未知值不覆盖已经保存的形式和签到码 |
| 空响应、裸错误文本可能被宽松解析为有效数据 | 严格解析 JSON，明确区分损坏响应和已确认结果 |
| 雷达遇到过期或服务异常仍继续后续探针 | 过期立即停止；服务错误、超时及前两次探针损坏的 200 响应标为待确认；正常请求及后两次交点的判定保持参考方案 |
| 数字提交缺少身份或签到码时仍可能发送 | 必要输入在写入前检查；损坏的已接受响应只读回确认，不重复写入 |
| 页面切换共用列表滚动位置 | 账号、课程列表及各课程历史分别保存滚动状态 |
| 密码字段被输入法当成普通文字处理 | 使用密码键盘并关闭账号/密码自动纠正 |
| 账号编辑时旋转屏幕，草稿及正在保存的状态丢失 | 独立内存 ViewModel 持有草稿和读写任务，取消、保存成功或永久销毁后清空；密码不进入恢复用 Bundle |

本地数据库结构和加密方式无需改动，已检查事务、默认账号转移、账号删除后日志保留、账号与密文绑定及中断记录恢复。没有为此次排查升级依赖或修改雷达坐标算法。
