# 安卓 1.0.3 流畅度优化

日期：2026-10-20。

用户反馈列表滑动、页面切换和操作响应不够顺畅。本轮检查界面编译报告与实际调用链，调整可确认的额外工作及等待行为。

## 已确认的问题与处理

| 原有行为 | 调整 |
| --- | --- |
| 列表显示后，仍等全部历史签到的人数和签到码查询结束才解除全局操作锁 | 主列表先交付，活动、人数和签到码独立后台补充；列表可滚动、打开详情和返回 |
| 四个日期一批，批次中最慢的查询阻塞后续日期 | 同时最多查询四个日期，各查询完成后继续下一个，短时间内到达的结果合并发布 |
| 刷新时在已有列表顶部插入再移除加载行，导致内容移动 | 已有内容保留，工具栏显示加载提示；空列表仍保留首屏加载提示 |
| 排序、合并、分组及补充数据导致的日期解析在界面线程执行 | 批量计算转到后台计算线程，界面只接收结果 |
| 每次详情先深复制整份学生名册，再读取本人状态和统计人数 | 直接只读解析名册，保留编号优先级、本人状态和人数口径 |
| 课程和日志行内联在列表中，时间文案在重组时重复格式化 | 抽取独立行组件，复用时间与账号展示文案，补充列表条目类型和稳定标识 |
| 相同补充结果仍创建新的签到对象 | 内容未变化时复用原对象，减少无效列表更新 |

打开详情、签到或编辑账号时，后台补充会暂停，让当前操作优先执行；仍在相同账号和课程时自动恢复未完成记录。返回或切换账号会取消旧任务，旧结果不再写回当前列表。补充数据不改写历史记录的本人签到状态。

手动刷新仍会查询最新数据：学校历史接口直接返回人数时使用本次响应；未返回时，即使界面暂时保留上一次人数，也会继续请求日期接口更新。

## 验证

使用虚拟账号与离线响应运行单元测试、静态检查、模拟器界面测试及优化安装包构建。覆盖重复提交、人数刷新、慢日期不阻塞后续日期、后台任务取消、详情打开后恢复补充，以及立即返回空记录时加载状态收尾。

| 检查 | 结果 |
| --- | --- |
| 单元测试 | 70 项通过，0 失败、0 跳过 |
| Android 16 模拟器 | 14 项通过，0 失败、0 跳过 |
| 静态检查 | 未发现问题 |

设备测试包含 43 条签到记录的慢查询场景：主动暂停人数响应，确认列表可滚动至最后一条、条目仍可点击，返回课程会取消查询，后续响应不会把界面切回旧课程。原课程滚动位置、账号操作、签到与日志检查继续执行。

```bash
./gradlew testDebugUnitTest lintDebug assemblePreview --offline --no-daemon
ANDROID_SERIAL=emulator-5580 ./gradlew connectedDebugAndroidTest --offline --no-daemon
```

界面编译报告确认原版本已经开启 Strong Skipping，并且已有签到行可跳过重组；本轮没有依据将所有卡顿归结为重组失控。新提取的列表行与展示文案复用遵循 [Android Compose 性能指南](https://developer.android.com/develop/ui/compose/performance)及[列表条目复用说明](https://developer.android.com/develop/ui/compose/lists)。稳定性判断参考[官方 Strong Skipping 说明](https://developer.android.com/develop/ui/compose/performance/stability/strongskipping)。

模拟器验证用于确认行为与功能，不能代表用户手机的帧率。本轮没有真机逐帧数据，不报告帧率提升百分比；滑动与切页体感需覆盖安装新包后复测。学校网络和服务器响应时间仍会影响数据取得速度。

优化包为 `app/build/outputs/apk/preview/app-preview.apk`，版本 1.0.3 / versionCode 4，沿用本机调试签名，可覆盖安装并保留账号和日志。
