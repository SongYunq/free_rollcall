# 业务层拆分计划

日期：2026-09-16

以下计划和验证记录对应首次业务层拆分；后续文档及备份整理见文末。

## 目标和边界

让 CLI 和桌面 UI 共用独立的 `rollcall_service.py`，本轮只做结构迁移。
不更换查询原理，不增加自动化功能，不重新打包。

本轮仅改动项目根目录文件。现有 `dist/`、`ios/`、`assets/`、`docs/`、
虚拟环境、编辑器配置和缓存目录均保持不动。验证使用 `python -B`，
避免生成或更新项目内的字节码缓存。

## 执行顺序

1. 在项目外的临时目录备份将要改动的顶层文件，以便回退和对照。
2. 将桌面版的五个业务函数与接口常量提取为 `rollcall_service.py`：
   `login_and_get_cookie`、`get_current_semester_info`、`get_courses`、
   `get_latest_rollcall_id`、`get_number_code`。
3. CLI 和桌面端导入这些函数，保留现有操作流程、时间格式化、UI 和线程逻辑。
4. 删除统一入口 `free_rollcall.py` 和旧打包配置 `free_rollcall.spec`。
5. 更新 README 和环境文档，说明源码入口、业务 API、验证方法和暂缓事项。
6. 添加根目录离线回归测试，运行测试、语法/导入检查，并与备份中的实现对照。

## 行为保持要求

- 不改接口 URL、请求方法、请求头、分页参数、课程筛选或字段名。
- 不改学生 ID 的请求监听方式、登录跳转顺序、Cookie 域过滤和等待时间。
- 保留动态学期查询及失败时的默认值 `29` / `12`。
- 保留课程去重、取签到列表最后一项的规则、字段兼容和返回值结构。
- GUI 仍依次尝试 Edge、Chrome、Playwright Chromium；全部失败返回空凭证。
- CLI 仍直接启动 Playwright Chromium；启动异常按原样抛出。
- service 不调用 input，不依赖 UI，默认不输出；调用端显式传入日志函数。
  合并后 CLI 的业务进度日志措辞采用共用实现，菜单和查询结果格式保持原样。

## 暂不处理

- 不加入会话文件、自动重新登录、无交互命令、JSON 输出或新的错误模型。
- 不顺带修改已有超时、分页、排序或异常处理策略。
- 保留独立旧脚本 `rollcall_capturer.py`，新调用链不引用它。
- 保留依赖清单及开发配置；PySocks 有代理兼容用途，本轮不删依赖。
- 旧应用及子目录内容不参与本轮迁移、验证或清理。

## 验证标准

- 离线覆盖学期查询、课程解析与去重、签到选择、签到码与状态返回、异常传递。
- 模拟浏览器覆盖直接捕获 ID、进入课程页触发 ID、捕获失败、浏览器回退和 Cookie 过滤。
- 模拟 CLI 菜单操作，验证其调用共用 service；导入 service/CLI 不加载桌面 UI。
- 对照迁移前后的接口请求与返回结果，检查桌面 UI 和线程代码没有变化。
- 检查变更仅发生在计划内的顶层文件。
- 未进行真实校园账户登录及在线接口验证时，完成说明必须明确这项限制。
