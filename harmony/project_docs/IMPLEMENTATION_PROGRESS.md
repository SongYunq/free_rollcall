移除主动“手动完成网页登录”按钮，验证码、必要人工处理自动显示原网页。新增 11 项完整流程测试，实际运行注入脚本与「进入课程」的账号登录、身份校验、网页关闭、学期查询、课程展示流程，包含手机版、电脑版、单页跳转、错误账号、隐藏验证码和取消晚返回。

## 登录提交与错误识别修复

2026-10-22：针对“正在使用账号密码登录／等待认证结果”停留，核对学校公开手机版 HTML、原始登录脚本及实际使用的 jQuery 3.6.1。学校将认证错误放在隐藏的 `#formErrorTip2`，再用全局 `#alert-box` 短暂提示；原实现漏读这些提示，又把按钮点击直接当成已提交。

现等待学校初始化、登录模式、加密函数及隐藏参数就绪，并确认全局 `#cllt` 属于当前密码表单。继续调用学校原按钮，只有原始校验完成、密码框禁用且加密字段生成，才进入等待认证状态；未接受的点击立即结束并提示。识别隐藏服务端错误和全局校验提示，明确错误不再依赖上次脚本是否成功返回。整页导航吞掉提交结果时，从原始表单标记恢复提交状态，避免重复填表和提交。用户名失焦会执行学校同步验证码请求，因此填写步骤单独保留 20 秒等待；初始化和总体登录仍有超时与取消保护。增加只含阶段名称的诊断日志，不记录凭据、页面脚本或完整认证地址。

## 用户自行验证顺序

1. Open `harmony/` 并完成同步，确认开发工具与 SDK 配套、最低系统保持 API 12；先完成原生编译。
2. 验证冷启动空账号、三个底栏入口、添加/编辑/默认/删除、重启后的本地数据与密码读取。
3. 使用自己的账号验证学校原网页自动登录、取消与人工验证码；检查切换账号后课程归属正确。
4. 检查当前学期课程、签到日期、数字码、已签到和迟到显示；断网刷新时应保留已有列表。
5. 如需真实签到，由使用者在适当场景自行验证；提交结果未确认时先核对日志，避免重复提交。

## 主要实现选择

- 最低系统为 API 12，界面和平台入口使用原生 ArkTS；业务逻辑与学校 JSON 解析留在普通 TypeScript，使同一份业务代码可以直接离线测试。
- 不复制 iOS 专属材质，改用鸿蒙胶囊底栏、模糊背景和基本无障碍名称，保持入口、排版和交互对应。
- 不把认证凭证放入共享网络 Cookie 容器；每次认证后取得的凭证仅用于对应账号的内存会话，提交请求不自动重试。
- 原生应用无第三方运行依赖。电脑端测试依赖 TypeScript，与华为提供的构建工具分别管理。
