# 鸿蒙客户端实施与验证记录

日期：2026-10-22

## 范围

在根目录新增独立 `harmony/` 原生工程，最低支持 HarmonyOS 5.0.0（API 12）。参考现有 iOS 的功能、页面、白底黑色列表和账号规则，未修改既有 iOS、安卓、Go、Python 或根目录账号文件。未创建提交或发布。

## 已完成

1. 应用和模块构建配置、Stage 入口、资源、图标、页面注册、网络权限及本机文件忽略规则。
2. 学校数据模型、课程与历史分页、个人出勤状态合并、数字码批量补齐、北京时间查询。
3. 数字签到、本人结果回读；雷达按原 iOS 参考版本移植计算与请求顺序。
4. 当前/默认账号分离、切换失败保留会话、同账号登录合并、只读请求过期重新认证、旧会话响应隔离。
5. 操作互斥，提交前持久化日志，提交前查询活动，提交失败与结果待确认分开；中断记录恢复与原账号核对。
6. Asset Store 密码存储与 Preferences 元数据；凭证修改失败回滚、元数据刷新失败恢复、账号删除保留日志。
7. 隐私网页登录、原始表单自动填写、人工验证码、身份核验、超时取消、独立内存认证凭证与禁止网络重定向。
8. 三个底部入口、课程/历史/详情、账号编辑和四个滑动动作、日志详情与核对；认证页面按尝试重建，忽略过期回调。
9. 独立 README、许可证、第三方代码说明及可重复执行的离线检查。

## 安装 DevEco 后的验证顺序

1. Open `harmony/` 并完成同步，确认开发工具与 SDK 配套、最低系统保持 API 12；先完成原生编译。
2. 验证冷启动空账号、三个底栏入口、添加/编辑/默认/删除、重启后的本地数据与密码读取。
3. 使用自己的账号验证学校原网页自动登录、取消与人工验证码；检查切换账号后课程归属正确。
4. 检查当前学期课程、签到日期、数字码、已签到和迟到显示；断网刷新时应保留已有列表。
5. 如需真实签到，由使用者在适当场景自行验证；提交结果未确认时先核对日志，避免重复提交。

## 主要实现选择

- 最低系统为 API 12，界面和平台入口使用原生 ArkTS；业务逻辑与学校 JSON 解析留在普通 TypeScript，使同一份业务代码可以直接离线测试。
- 不复制 iOS 专属材质，改用鸿蒙胶囊底栏、模糊背景和基本无障碍名称，保持入口、排版和交互对应。
- 不把认证凭证放入共享网络 Cookie 容器；每次认证后取得的凭证仅用于对应账号的内存会话，提交请求不自动重试。
- 原生应用无第三方运行依赖。电脑端测试依赖 TypeScript，与华为提供的构建工具分别管理。
