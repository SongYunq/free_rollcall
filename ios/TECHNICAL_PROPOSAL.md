## 1. 目标和改动范围

在 `ios/` 内完成可独立开发、编译的原生 iPhone 工程。整个目录可以单独复制使用，不调用、嵌入或依赖上层 Python、旧桌面程序、电脑常驻进程或自建服务器。

第一版提供三个入口：**功能、本地日志、账号管理**。默认进入功能页，功能页只提供“进入课程”模块；课程内可以查看签到历史、取得数字码，并由用户点击正在签到的条目直接提交。

- 最低部署版本为 **iOS 18**
- iOS 26、27 及更新版本采用原生液态玻璃及交互效果；iOS 18 至低于 26 的系统保留相同操作，使用普通磨砂材质
- 数字签到按学校接口提交并核对本人状态
- 雷达完全参考指定 `bot/` 的方案；不申请位置权限，不以线上验证为开发前置条件
- 根目录命令行、业务层、旧应用和其他目录保持原样；参考仓库不作为运行依赖
- 只交付代码工程和必要文档；本轮不创建备份、不创建分支、不进行 commit 或发布

## 2. 界面和交互

### 2.1 全局视觉

应用自有页面统一白底、黑色主题，正文黑色、次要内容灰色、分隔线浅灰。学校登录网页保留原样式。

功能入口、课程、签到历史、账号和本地记录均采用纵向长条列表。长标题可以换行，时间与数字码使用等宽数字，状态与按钮由布局对齐，不用空格凑列。结果同时用文字和图标表达；删除操作保留系统破坏性提示。

### 2.2 三个底部入口

| 从左到右 | 页面 | 内容 |
| --- | --- | --- |
| 1 | 功能 | 当前账号状态、进入课程 |
| 2 | 本地日志 | 本机全部账号的签到操作记录 |
| 3 | 账号管理 | 多账号配置、默认设置和手动登录 |

底栏为悬浮胶囊，三个图标从左到右排列，各页面保留自身状态。常规页面始终可切换入口，列表末尾预留底栏空间。图标提供可访问性名称和选中状态，支持系统大字号、减少动态效果和降低透明度。

iOS 26 及以上使用 `TabView`（系统标签栏容器），由系统处理玻璃材质、选中效果、交互动画和滚动边缘；不额外覆盖实心选中胶囊或底栏背景。仅显示三个图标，保留可访问性名称，不随滚动收起。iOS 18 至低于 26 保留普通磨砂胶囊与相同入口。通过系统可用性判断隔离实现，降低透明度与减少动态效果由系统标签栏自行适配，旧版底栏保留对应兼容处理。

### 2.3 页面路径

| 页面 | 展示 | 点击行为 |
| --- | --- | --- |
| 功能 | 当前／默认账号；“进入课程”长条模块 | 确保登录后进入课程列表 |
| 课程 | 账号信息及学校当前学期课程 | 进入该课程签到历史 |
| 课程签到 | 课程、账号、时间、形式、状态、可用数字码 | 可签到条目直接提交；其余查看详情 |
| 签到详情 | 课程、时间、形式、状态、数字码或雷达标识 | 下拉刷新；确认可签到时提供提交按钮 |

活动条目明确标注“点击此条目签到”。点击即授权本次提交，不再增加重复确认；提交过程中保留码和进度，防止连点重复请求。

## 3. 多账号和登录规则

### 3.1 保存和编辑

账号管理右上角提供添加入口。保存账号、密码和可选备注，不要求添加时立即登录；第一个账号自动设为默认，以后由用户主动选择。

账号去除首尾空白，密码原样保存；只检查非空，不检查学号、邮箱或密码正则格式，关闭自动大写和自动纠错。相同账号文本不重复添加。编辑时密码默认可见，并提供显示／隐藏按钮；列表不展示密码。

密码保存到本机系统钥匙串，普通数据只保存账号配置、备注、默认标记和已验证的内部学生标识。应用不读取上层 `account.json`，不将密码、认证凭证或完整学校响应写入日志。

### 3.2 账号左滑四个动作

手指从右向左滑动，展开行右侧操作区；关闭完全滑动直接执行，用户必须点击具体动作。

| 动作 | 行为 |
| --- | --- |
| 登录 | 用该账号认证；成功后成为全应用当前账号，不修改默认选择 |
| 修改 | 修改账号、密码或备注；改动当前账号凭证后使旧会话失效，只改备注则保留会话 |
| 默认 | 将该账号设为默认，不触发登录、不切换当前会话 |
| 删除 | 确认后删除账号与密码；删除当前账号则退出，删除默认账号则清空默认选择；历史日志保留 |

删除默认账号后，不自动选择其他账号代替。登录或签到进行中暂缓账号修改、删除和切换。

### 3.3 当前账号优先于默认账号

| 场景 | 行为 |
| --- | --- |
| 启动 | 默认功能页，暂不登录；账号和日志可直接查看 |
| 尚未登录，点击功能模块 | 自动登录默认账号，再继续原操作 |
| 没有默认账号 | 引导添加、设为默认或主动登录，不任意选账号 |
| 默认 A、手动登录 B | 后续所有业务使用 B |
| 修改默认选择 | 不改变当前已登录账号 |
| 当前 B 失效 | 重新认证 B，不退回默认 A |
| 切换 B 失败 | 保留之前仍有效的 A 会话 |
| 切换底部页面 | 保留当前登录状态 |
| 结束进程后重新打开 | 重新进入未登录状态；账号配置、默认选择和日志保留 |

登录任务按账号合并；每次登录使用独立网页数据和原生网络会话。切换成功后清空旧课程、签到数据和导航选择。请求绑定会话版本，旧账号的延迟响应不能覆盖新账号页面；提交绑定操作开始时的账号快照。

### 3.4 自动认证和人工处理

采用学校原网页的既有登录流程：加载页面、等待表单、填写账号密码、触发原按钮、等待跳转、核实身份。原页面负责密码加密及认证规则，密码以脚本参数传入，仅在已核实的学校认证域填写。

- 明确的凭证错误提示修改后重试；同一账号连续三次失败后显示当前网页登录页面
- 网络失败不计入三次错误，不自动反复提交同一份错误密码
- 遇到验证码、锁定或额外认证时提前交给用户在原网页处理
- 人工登录后核实身份；不能把网页中另一个账号的课程和结果绑定到原选择账号
- 加载和响应有超时、取消及失败提示；不因没有课程而无法取得身份

## 4. 课程与签到历史

课程查询与原服务层保持一致：先读取学校返回的当前学期和学年，再使用 `semester_id`、`academic_year_id`、`classify_type: recently_started` 等条件筛选。只展示本学期课程；若结果有多页，内部自动取齐，页面不提供“加载更多课程”按钮。下拉刷新会重新获取学期信息；学期获取失败时提示重试，不使用固定学期或改查所有课程。

签到历史尽可能继续加载，不固定只取最近一次，也不将一次请求的 99 条当作总上限：

1. 有明确分页信息时按其推进
2. 没有分页信息时，短页仍允许继续尝试下一页
3. 按签到标识去重；空页、重复页或无新增记录时停止
4. 对无法证明完整的数据，说明当前取得的范围，不显示“已全部加载”
5. 同一课程刷新或翻页失败时保留已有内容；换课程时清除旧课程数据
6. 翻页保留已经取得的数字码和刚确认的本人结果
7. 活动排在前面，其余按有效时间倒序；缺失时间或未知类型如实展示

只有确实只能可靠取得最近一条时，才采用用户允许的“最近一次”降级。当前已取得多条历史，不使用该降级。

活动状态与本人结果分开判断：活动进行中不代表本人尚未签到。结束状态优先于可能过时的 `is_expired=false`，超过结束时间也不再提供提交。类型根据明确的数字／雷达字段识别，不能因缺少数字码就推断为雷达；其他形式提示暂不支持。

数字码优先读取当前活动和用户打开的详情，不逐条读取全部历史详情。详情虽然包含全班列表，只提取本人信息，不保存或展示其他同学的数据。

## 5. 点击签到与结果处理

### 5.1 一次操作的过程

1. 固定账号、课程和活动，限制重复点击和账号切换
2. 持久化一条“处理中”日志；若保存失败，停止提交
3. 确保当前账号登录，刷新活动及本人状态
4. 已结束、状态未确认或不支持的类型停止提交；本人已经签到则只更新状态，不重复写入学校端
5. 展示取得的数字码，保留前导零；缺失码不当作 `0`
6. 执行对应的数字或雷达提交流程
7. 更新同一条日志及页面状态，保留账号快照和结果原因

提交前登录、详情读取或校验失败也保留本次操作记录。打开课程或查看历史不生成签到日志。

### 5.2 数字签到

向已知的数字签到地址提交数字码和新设备标识。收到响应后再次查询本人状态；取到码、请求成功返回或按钮已点击都不足以判定业务成功。

断网、超时或写入后无法确认结果时标记“待确认”，不自动重放请求。用户可在本地日志使用原账号核对学校端结果，核对只读，不再次提交。

### 5.3 雷达签到

固定参考[签到机器人参考项目](https://github.com/KrsMt-0113/XMU-Rollcall-Bot)的 `c7de02b11da3433a047bab29dbbbbbb4c855a484`，移植 `verify.py` 的 `send_radar`：

- 两个预设点：`(24.3, 118.0)`、`(24.6, 118.2)`
- 相同请求地址、方法、相关请求头、精度、高度与空值字段；每次请求新设备标识
- 读取距离反馈，使用相同投影、地球半径 `6371000`、两圆交点计算和经纬度还原
- 相同的两个预设点及两个候选点尝试顺序、提前返回逻辑和解析顺序
- 成功沿用参考方法的 HTTP 200 规则，不增加另一种成功判据
- 不读取手机位置，不申请定位权限，不增加真实定位分支或额外试点

多个候选点仍属于一次用户操作，只保存一条日志。应用外围负责账号归属、连点控制、网络异常与待确认状态，不改变正常算法流程。

按用户决定，开发只检查源码和离线一致性，不进行雷达线上有效性验证。参考版本、对照范围与许可见 [技术审阅](project_docs/BOT_REFERENCE_REVIEW.md) 和 [第三方声明](THIRD_PARTY_NOTICES.md)。

## 6. 本地日志

| 必要字段 | 保存及展示 |
| --- | --- |
| 时间 | 操作开始时间，按上海时区显示，另存完成时间 |
| 课程名称 | 当时课程名及内部标识 |
| 签到形式 | 数字、雷达、其他或未知 |
| 成功与失败 | 成功、失败；另保留处理中、待确认，避免误判 |
| 账号信息 | 当时账号与备注快照，不含密码或认证凭证 |
| 签到码 | 实际数字码；雷达显示“雷达签到”；尚未取得则明确标记 |

日志保存在本机，默认时间倒序，无需网络或登录即可阅读，不云同步。删除或修改账号不改写历史快照；进程中断留下的“处理中”在重开时变为“待确认”。核对必须使用原账号，不能自动换账号查询或提交。

## 7. 独立代码结构

| 文件或目录 | 职责 |
| --- | --- |
| `FreeRollcall/App/FreeRollcallApp.swift` | 应用启动、持久化初始化 |
| `FreeRollcall/App/AppState.swift` | 当前账号、登录任务、页面状态、本学期课程和签到协调 |
| `FreeRollcall/Services/WebAuthenticator.swift` | 原网页认证、人工接管、身份和凭证交接 |
| `FreeRollcall/Core/TronclassClient.swift` | 网络隔离、课程／历史／详情、数字签到与结果查询 |
| `FreeRollcall/Core/RadarSubmission.swift` | 参考方法的雷达计算与提交 |
| `FreeRollcall/Core/Models.swift` | 身份、课程、状态、分页、去重 |
| `FreeRollcall/Storage/LocalStore.swift` | 多账号、钥匙串密码、日志及中断恢复 |
| `FreeRollcall/Views/` | 三个页面、课程、历史、编辑和网页登录 |
| `CoreTests/`、`AppTests/`、`UITests/` | 核心、会话与存储、关键交互检查 |

使用 Swift、SwiftUI、WebKit、URLSession、Keychain、SwiftData；核心模块作为本地 Swift package 与工程一起保留。无需安装参考机器人的依赖。第一版职责集中在少量组件，不额外建设通用框架。

调试样例仅在显式运行参数下使用内存数据，正式构建不含样例入口。构建产物位于已忽略的 `.build/`，开发记录集中到 `project_docs/`。
